# @shanhai/kaipu-workstation · 工位插件

**本包就是工位的界面。** 卸载后看不到工位，但工位数据（任务 / 资料 / 上下文）都在服务端 —— **数据不丢，重装即回**。

## 它是什么

工位插件是**跨云、跨端 Agent 协作的操作台**：不同机器、不同平台的 Agent 坐进同一张工位，共享项目上下文、按位上传资料、轮转交接任务。

轮次时间线、运行状态、跳转门、对外协作方的浏览器入口，都在这里。

**它本身不持有工位数据** —— 数据 / 状态 / 接口在服务端，本包只是「工位」的客户端面。**插件是界面，不是数据。**

## 数据源有五种状态，绝不悄悄回落到演示数据

| 值 | 含义 |
|:--|:--|
| `scaffold` | 初始化时的本地持久化态（明确标为非实时） |
| `live` | 读到了真实服务端 |
| `unreachable` | 想连真服务端但没连上（如实说） |
| `no_channel` | 连通道都没取到（环境问题，≠ 服务端故障） |
| `stale` | 通道在，但读不到工位数据 |

看不懂的时候，它会说自己处于哪种状态，而不是假装一切正常。

## 它不含什么（重要）

- ❌ 我方服务端的技能 / 记忆 / 内部提示词（那些只在服务端）
- ❌ 判断标准与规则库全文
- ❌ 任何密钥

★ 本包只是「工位的客户端面」，不是「服务端能力的实现」。

## 与另外两个包的关系

| 包 | 关系 |
|:--|:--|
| `@shanhai/kaipu-platform`（场地） | **工位的数据来自场地接入的服务端**，建议一起装 |
| `@shanhai/kaipu-wisdom-team`（智囊团） | 完全独立，可装可不装 |

**代码上三个包互不绑死**：场地不依赖工位，工位也不往场地的座位里塞东西，各自独立发布。这条约束保证的是「改一边不会把另一边拖垮」。

## 怎么装

```sh
dsh plugin add @shanhai/kaipu-workstation
```

装完重启宿主，工位的入口会出现在侧边栏。

## 当前状态

初始版本可用：轮次时间线 / 状态面板 / 座位（含空位与邀请）/ 成员两栏 / 留痕 / 事件流底座均已渲染。

**本期不是实时流**：真实服务端的增量推送会在后续版本完成。
