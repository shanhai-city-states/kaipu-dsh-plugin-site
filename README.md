# 山海·开铺

**给 AI Agent 开一家公司。**

你不再是一个人对着一个聊天框。你把 Agent 招进来，分给它一个位子、一份职责、一条汇报线；它干的每一件事都落在纸面上，谁批的、谁审的、什么时候交的，全都留着。

出了问题，你能翻回去看是哪一步错的。做对了，你也能翻回去看是哪一步对的。

---

## 这是什么

一个装进 DeepSeek Harness 的插件。装上之后，你的 DSH 里会多出一间「工位」。

在工位里，你可以：

- **建项目** —— 一件事从头到尾是一个项目，不是一堆散落的对话
- **派人** —— 把 Agent 放到具体的位子上，而不是笼统地「叫 AI 帮我做」
- **派活** —— 派单有标题、有交付物、有截止时间
- **验收** —— 它交的东西你过一眼，通过或是打回，理由都留在项目里

没有工地，就没有工序。**这是它和「随便找个 AI 聊两句」的根本区别。**

---

## 核心：位子，不是机器人

工位里最小的工作单位不是「一个 Agent」，是**一个位子**。

一个位子有它的职责范围。Agent 坐进去，就按这个位子的规矩干活。换个 Agent 坐同一个位子，规矩不变。

常见的工作位有三类：

| 位子 | 干什么 |
|:--|:--|
| **执行位** | 真正干活、交东西的 |
| **审计位** | 不干活，专门挑毛病的 |
| **管理位** | 看全局、做协调、拆分任务的 |

除了这三类，还有战略位、管理助理位、连接器位（给机器用的接口，比如把群消息接进来派活）。

**「签字位」是平台自己的效力锚点，你不需要、也不能往里派人。** 拍板的人始终是你。

**它自己会算「我中不中立」，而不是自称中立。**

工位里有一组中立性读数，是系统自己算出来的，不是人工勾的：

- 这个铺子**有没有真的拒绝过**人？从没拒绝过，「可以拒绝」就只是文案
- 我们**自己的项目**是不是也走同一套审计？自家例外，标准就是给别人定的
- 客户能不能**不经过我们**就把证据验完？必须回来找我们，中立就被绑架了
- 席位**能不能换成第三方**？换不掉，「候选」只是客气

这几条算不出来或者数据不全，结论就是**未通过**——宁可判未过，不默认通过。

## 流程：六个阶段，一步一步走

一个项目从立到收，走六个阶段：

```
立需求 → 出计划 → 派任务 → 动工 → 验收 → 归档
```

**不能跳阶段。** 你从「立需求」直接想进「验收」，系统会拦住你，并说明缺了哪一步。

每个阶段都有它的产出物。计划阶段产出一份计划书，动工阶段产出一份交付物。**到了该交东西的时候没交，系统会提醒你补上理由** —— 这一步我们做的是提醒而不是硬拦，因为有些工作确实可以先推进后补件，硬拦反而会逼人绕路。

---

## 留痕：这是整件事的底子

工位里发生的一切都记账：

- 谁在什么时候、把哪个任务、改成了什么状态
- 谁审的、审出什么、凭什么打回
- 每一条都带时间、带人、带理由，可以按项目倒着翻

**交付物另外加一层保护。** 你交上来的东西被打包成一个归档包，包里每个文件都算一个指纹，所有指纹再合成一个总指纹。别人拿到这个包，可以自己重新算一遍，看跟你当初交的是不是同一份 —— 不需要信任我们。

这套算法是写死的、公开可复算的，谁都能验。

**这里要说清一件事**：我们说的「可独立验证」指的是**归档包没被动过**。它不是「整本操作日志的每一条都首尾相扣」。

前者是现在就能做到的，后者需要更完整的设计。我们不在这一点上含糊 —— 把还没做到的说成做到了，是比不做更坏的事。

## 边界：它不做什么

这几条我们主动说清楚，因为很多产品在这上面含糊过去：

**它不替你做判断。**

工位管的是「流程走没走对」—— 该不该有这一步、该不该到这个人、该不该留这个痕。
至于「这个活干得好不好」，那是判断标准的问题，标准由你定、由你配置。工位只负责把标准执行到位，并把执行过程记清楚。

**它不训练模型。**

你的 Agent 该是什么水平，取决于你用的是什么模型、你怎么配置它。工位不改你的模型权重，也不做任何形式的模型训练。装上前和装上后，模型还是那个模型。

**它不上传你的提问。**

你的数据在你自己这边。工位不把你的对话内容发往我们的服务器。

（有一条本机的输出检查：Agent 生成的答复在给你之前，会先过一遍跑在**你自己机器上**的内容审查服务，用来拦技术敏感信息。这一层不走外网。）

**它的判断标准不开源，流程骨架开源。**

这不是藏私。是因为一旦把判断标准摊开写死，它就只能守那一套标准；你需要的是能配置的骨架，而不是一个写死了答案的黑盒。

## 怎么装

1. 打开你的 DeepSeek Harness
2. 在插件市场里搜索「山海·开铺」
3. 安装，重启宿主，工位的入口就会出现在侧边
  
装好之后，先给自己开一个项目试试。一个人也能用 —— 你既是老板，也是唯一的员工。

### 三个包，装哪个

本仓是一个仓库里的三个插件，各自独立安装、独立卸载：

| 包 | 目录 | 是什么 | 要不要装 |
|:--|:--|:--|:--|
| `@shanhai/kaipu-platform` | `packages/plugin-platform` | **场地插件**（核心）：场景、运行记录、报告 | **必装** |
| `@shanhai/kaipu-workstation` | `packages/plugin-workstation` | **工位插件**（操作台）：轮次时间线、运行状态、成员与留痕 | 想在 DSH 里直接操作工位就装 |
| `@shanhai/kaipu-wisdom-team` | `packages/plugin-wisdom` | **智囊团插件**（可选）：配套侧边面板 | 可装可不装 |

后两个都依赖场地插件的数据（数据来自场地网关），单独装会如实显示「通道未就绪」，不会假装正常。

## 给技术同行

这个包是 DeepSeek Harness 的插件形态。它跟宿主之间通过约定的接口通信，不感知宿主的内部实现。未来如果你想把它接到别的宿主上，理论上可以，但这条路我们还没有验证过，不承诺。

**本仓包含**：三个插件的可安装产物（`packages/*/lib/`，即发到用户机器上的那一份）、接入契约（`contracts/`，含错误码 / 席位 / SSE 事件定义）、市场条目。

**本仓不包含什么，我们写清楚**：

- ❌ 服务端的判断标准与规则库全文 —— 这些在服务端，不在客户端包里
- ❌ 任何密钥、任何客户数据
- ❌ 内部质检脚本

**为什么代码开源、判断标准不开源**：判断标准一旦摊开写死，它就只能守那一套；你需要的是能配置的骨架。壳开着，钥匙不外露 —— 这是我们对「开源」这件事的边界。

要深度定制或对接自己的系统，请用 `contracts/` 里的接口定义；需要更多支持，联系我们。
